# 路线编辑器中的脚本动作

「编辑坐标路线」的下方列表支持混合显示录制键鼠、普通脚本动作与彩色纠正点。
「等待小怪消失」可直接插入，默认连续 5 s 无小怪才继续；「插入脚本动作」菜单复用主脚本编辑器的分类和配置窗口，包含键鼠、识别、流程、窗口/软件以及脚本引用、逐行插入、指定行插入。
游戏坐标浮窗和开始录制是工具入口，不属于可插入动作。

新动作放在当前选中行下方，默认间隔 500 ms，后续输入、纠正点与轨迹时间一起后移。双击编辑参数，支持删除和上下移动；取消路线编辑不会改动原脚本。
纠正点只记「距上一点的间隔」（起点固定为 0）：在某个纠正点之前插入动作或延时只会加长它前面那一段间隔，它后面的纠正点跟着顺延，不用逐个改时间；间隔都非负，所以纠正点列表的顺序就是时间顺序，上下移动就是调换两个纠正点的先后。
原来的「插入延时」继续用于把路线时间轴后移；菜单中的「延时」是可编辑的普通延时动作行。

执行普通动作前释放录制按键并刹停，普通动作的执行前/后延时及阻塞时间不计入路线时间轴。动作结束后恢复录制按住状态并续播。等待小怪、延时、阻塞期间允许此前开启的光标跟随工作，录制镜头输入仍由路线独占。

## 从当前行开始执行

键鼠连续路线编辑器里右键任意一行（键鼠输入、插入的脚本动作或纠正点）可选「▶ 从此行开始执行」，无需从路线起点重放：

- 先按这一步录制时刻的轨迹采样把角色直线带到位并校正朝向（与纠正点纠偏同一套逻辑），这一步之前的步骤不再回放；纠正点行从它之后的第一个输入开始。
- 路线时钟从该步的录制时刻起算，之前的按住状态按录制恢复，之后的纠正点与终点验收照常执行。
- 试跑只把编辑结果写回脚本（等同确定，需要保存），动作交给执行入口时用临时副本携带 `start_step_index`，不改变脚本里保存的内容；`start_step_index` 只允许指向路线内的步骤。

跳转以路线中的输入/动作行为目标，纠正点不占跳转行号。跳转后重建目标位置之前的录制按住状态并重置路线时钟。路线全局识别模块拥有独立作用域，遵循主播放器的启用设置；退出路线时注销，外层脚本的守卫跳转继续向外传递。

## 不在这一局游戏里就跳过

路线动作（键鼠连续路线与坐标跑图）在执行前与执行中都会确认「人还在这一局游戏里、战斗端在前台」：战斗端没开、没进对局、内存/状态读不出来、换图或切场景、战斗端不在前台（自动切前台失败）时，记一条「跳过…／…中断…」日志并跳过剩余步骤，脚本继续往下执行，输入不会发给别的窗口；只有死亡、坐标无效、导航超时这类真正的执行错误才会中止脚本。终点验收（走到终点姿态并校验落地）失败同样只记「终点验收跳过」，不再让整场异常收尾。

本次复用现有 `ScriptsMixin`、动作分类、配置对话框、动作摘要、播放器分发与全局作用域回调，没有增加第三方依赖。
2026-10-14 GitHub 检索 `SSJJ tkinter macro route editor actions` 未找到同时满足 SSJJ 路线与本项目动作语义的成熟实现；通用宏项目不能直接替代已有引擎，因此不引入其他编辑器。
