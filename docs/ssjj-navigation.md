# 生死狙击路线记录与跟随

当前提供第一层能力：手动走过一段路线，记录本人实时坐标，再让 Macro 根据坐标与朝向跟随一遍。首选短距离、平地、没有机关的路线。还没有自动避障、跳跃、爬梯、复活续跑或从任意位置找路的能力。

## 软件内使用

通过 `run.bat` 重启源码，在脚本编辑区选择 **录制/脚本 → 游戏坐标**。浮窗每约 100ms 更新地图 ID、XYZ、朝向、存活/落地状态，不主动抢焦点；读取在独立线程进行。游戏断开后显示原因并尝试重连，失效坐标不能用于录制。窗口或无边框模式便于看到浮窗；独占全屏下的覆盖显示未验证。

1. 新建或打开普通脚本，在列表中选中要插入路线的位置。
2. 浮窗点击 **开始录制路线**，切回游戏，手动走到目标位置。
3. 点击 **停止并插入脚本**，生成一条 **坐标跑图** 动作，然后保存脚本。路线点直接存入脚本 JSON，不依赖外部 Python 文件。
4. 把点击、按键等动作插在路线前后。多段移动分别录成多条路线，适合“走到入口 → 交互 → 走到出口”的流程。

录制路线时先停掉普通 F8 键鼠录制，避免把同一段移动记录两遍。坐标路线保存沿途点与终点；拐角要实际走过，不能只凭一个远处终点保证绕过障碍。也可以通过 **导入路线** 使用此前的 `examples/python/ssjj_route.json`。**复制坐标** 便于记下位置，但复制的文本不是执行动作。

浮窗拖动标题可移动。录制期间切图、死亡、状态过期或传送会使当前路线无效，需要取消后重录。关闭浮窗前要求插入或取消路线；退出主程序时，会尝试把有效路线插入草稿，无法保存时阻止退出并说明原因。

### 后台读取与后台输入

坐标读取不要求游戏前台。但当前自动跑图仍要求游戏前台，失焦会停止，不能让游戏最小化后自动跑图并同时使用键鼠做其他事。

2026-10-11 的定向消息探测：游戏在后台，`PostMessage(WM_KEYDOWN/UP)` 的 W、A 均成功入队，状态时间持续更新，但两个方向的坐标位移均为 0。因此本次没有启用未经验证的“后台输入”选项，也不自动抢回前台。现有只读坐标模块只能告诉控制器角色在哪里，不能直接让角色移动；真正的后台执行还需要单独验证可用且隔离于用户键鼠的游戏输入通道。失焦运行与最小化运行也不能视为同一能力。

## 数据来源与支持范围

- 外部只读 `OpenProcess` / `ReadProcessMemory`，没有注入或内存写入。只读取本人状态和地图 ID，不收集其他玩家的位置。
- 根据已加载的 Mono 元数据查找类与字段。运行时布局只支持已核实的 x64 `mono-2.0-bdwgc.dll`，SHA256：`7cf37b3415c2a168c724163be78109323ca6f75112eb549f2197a528eaebb4c9`。版本变化明确报错。
- 坐标来自 `MyPlayerEntity.BasicInfoComponent.Current` 的游戏状态快照，可能存在更新延迟；使用原始 XY 水平坐标、Z 高度，朝向使用 `_viewYaw`。
- 当前实读地图 ID 为 `100001`，与 `E:\SSJJ-map-analysis` 的缓存版本 `9a81a2a5059f8b732da623f373b38c81` 对应。离线三角网包含场景几何，不代表可行走网格，所以首版使用实走路线，不据此猜测通路。

## 使用

日常仍通过根目录 `run.bat` 启动最新源码，不需要 exe 构建。以下只读录制命令在项目根目录的 PowerShell 执行，使用与 `run.bat` 相同的 Python 和依赖目录：

```powershell
$env:PYTHONPATH="$PWD/.deps;$PWD/src"
& 'C:/Python313/python.exe' -m macroflow.execution.ssjj_state
```

命令只打印当前地图、本人坐标、朝向与状态。需要游戏已进入关卡，而且只有一个战斗客户端运行。

录制 30 秒路线，5 秒后开始：

```powershell
& 'C:/Python313/python.exe' -m macroflow.execution.ssjj_navigation --output examples/python/ssjj_route.json --seconds 30 --delay 5
```

切回游戏，手动走路线。每相距约 100 游戏单位记录一个点，并保留终点；死亡、切图或坐标大幅跳变会中止。没有走出有效路线会报错，已有路线文件只在新路线有效时替换。

录制结束后回到原起点，在 Macro 中打开 `examples/python/ssjj_follow_route.py`，通过现有 Python 脚本播放入口执行。脚本等待 5 秒，让你切回游戏，然后自动校准鼠标转向、逐点转向和前进。路线文件必须与该脚本在同一目录；可以复制这两个文件保存多条路线。

开始时需落地，并距起点不超过 250 游戏单位。到点阈值为 80，包含高度差。前进采用最长 150ms 的 W 按键脉冲，复用现有底层输入；专门的 `ssjj_input` 接口在父进程发送前再次核对状态，暂停、停止或失焦时释放 W，不跨暂停持续按住。暂停与 RPC 排队时间不计入控制超时。失焦、角色死亡、地图改变、状态读取失败、快照未更新、鼠标校准失败、前进时 3 秒没有接近目标或单点耗时超过 30 秒都会中止并报告原因。停止后重新执行会从路线开头开始。运行时不要手动改变朝向或移动。

本次已随附实际录制并完成自动跟随的 `examples/python/ssjj_route.json`：地图 `100001`，39 个点，长度约 4188.6，起点 `(7411.51, 1510.58, 519.79)`，终点 `(5162.56, 983.81, 519.79)`，所有点高度一致。执行前需回到录制时开始走路的位置，也可按上面的命令从自己选的位置重新录制并覆盖它。
