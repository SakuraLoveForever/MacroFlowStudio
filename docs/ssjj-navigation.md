# 生死狙击实走路线录制与跟随

2026-10-13 更新。通过项目根目录 `run.bat` 使用最新源码，无需构建 EXE。

## 软件内录制

1. 打开实时坐标面板，进入目标地图，开始录制。
2. 起点按 F7，然后实际走过路线。软件自动保存途中发布的新坐标（轮询间隔约 50ms），不再只连接首尾标记。绕墙的拐角与高差会留在轨迹中。
3. 行进中的跳跃、交互、切枪、按钮与滚轮会记录下来。F7 可继续添加需要对齐视角的标记点。
4. 需要原地操作时：停住并转正 → F6 → 操作并松键 → 原处 F7 → 继续行进。
5. 终点按 F7，再按 F8 停止并插入脚本，保存脚本。最后标记后如果移动超过 20 个原始坐标单位，需要补充终点。

至少需要两个标记。F6/F7 不录入动作，重复按下不重复标记，快捷键冲突会明确提示。鼠标移动与 WASD 不作为原始输入回放；行进方向由实走通路决定，每个标记点校准 yaw/pitch。这仍不等于复现侧移、倒退或独立瞄准。

**旧版只有标记点、没有 `trajectory` 的录制需重新录制。** 不会把缺失通路补成直线。保存的动作仍是普通脚本中的 `ssjj_recording`，无需 Python 脚本或新依赖。

## 回放方式

回放前回到起点附近，保持游戏前台。距起点超过 250 会停止并提示；系统没有证据证明陌生区域到起点可达，因此不自动跨地图直冲。附近起点定位仍是短直线，应保持两者之间通畅。

标记点之间按录制轨迹顺序前进，保留拐角，不搜索邻近的后续路段；交叉路线不会因位置相近直接跳段。路线中间点使用更紧的 12 单位容差，终点验收容差为 20。这些是游戏原始坐标单位，不是米，也不代表实机测量精度承诺。

行进动作按录制时对应的通路距离触发，变速后不会仅因经过固定毫秒数就提前/延后跳跃。同一行进段中的成对按下/释放保留原按住时长；待释放的键与其他空间动作独立调度，同一个键再次按下仍需等先前释放。超过客户端采样间隔的空间精度无法保证，实际偏差还取决于运动速度与反馈时延。

录制中相同位置的持续新状态表示原地停留：回放到该位置暂停前进，执行该位置的等待与动作后继续。重复读取同一未更新快照不制造额外停留。F6 和最后标记之后的局部动作继续保留时序；最后标记之后不能继续录制未标记的行进。

暂停、守卫处理和转向等待会释放输入并冻结动作时钟；继续行进后才恢复行进动作。导航与动作各自有输入租约，阻塞、失焦、停止时仍能释放按键。到点后等待落地，再对齐目标视角。

## 状态与错误反馈

- 仍使用只读 `SSJJReader`，不注入、不写游戏内存。支持的 Mono DLL SHA256：`7cf37b3415c2a168c724163be78109323ca6f75112eb549f2197a528eaebb4c9`；不匹配明确报错。
- 每次读数核对前后状态时间、本人对象、状态对象及地图，发生变化最多尝试三次；仍变化则报错。这是跨进程读取的一致性检查，不是游戏提供的原子快照。
- 确认向目标反方向累计移动时明确报告“实际移动方向与目标相反”，释放输入，避免一律标为卡住；不会根据少量异常位移擅自翻转坐标轴。
- 偏离当前录制路段超过 80、死亡、切图、快照一秒不更新、坐标跳变、转向失败、三秒无进展或单点超过 30 秒会停止。录制停留/暂停/守卫等待不计入导航无进展时长。
- 未知动态障碍不会自动随机侧跳。绕行依赖已经录下的通路，不是自由探索地图或自动战斗。已读到怪物/Boss 的研究探针尚未接入本功能。

运行日志区分首点定位、行进、定点动作与当前标记，包含输入计数和方向/坐标反馈。执行成功表示路线与输入完成，不表示开关已成功交互或关卡已通关。

## 原生坐标路线

已有 `ssjj_route` 动作及 JSON 导入仍表示用户提供的坐标点序列；它本身没有录制动作。应提供真实拐点，不能靠两个端点获得绕障规划。命令行只读录制 `macroflow.execution.ssjj_navigation` 和 Python 示例仍可用于这种显式路线；它们与软件内带空间动作的 `ssjj_recording` 是两种不同动作。
