# 生死狙击路线记录与跟随

软件内录制路线会同时保存键盘、原始相对鼠标位移、鼠标左/右/中键、滚轮和同期坐标/朝向。回放按原操作与原始时序发送输入，用坐标检查是否偏离；不会另行自动按 W 或校准转向。跳跃、蹲下、交互等已录下的按键会原样回放，但不代表具备自动判断障碍、爬梯或复活续跑能力。

录制鼠标转向时，复用普通录制的游戏光标居中检测：只有游戏前台且光标在游戏窗口中心附近，才接收原始位移。点击浮窗后移回游戏的桌面光标移动不再记成转向；键盘按下/松开不受此条件影响。请先点击游戏恢复视角控制再操作。居中检测是游戏锁定视角的判断依据，未验证使用自由光标控制视角的游戏模式。

回放日志分别列出键盘和鼠标事件数量；偏差停止时记录时间、已发送输入数量、实际及录制坐标，便于区分输入未录入和回放偏离。已经混入桌面位移的旧录制无法可靠自动清理，需要重新录制。

单独的 `ssjj_route` 坐标导航与下方 CLI 纯坐标录制仍用于根据坐标跟随平地路线；它们没有键鼠操作记录，不等同于软件内新录的键鼠路线。

## 软件内使用

通过 `run.bat` 重启源码，在脚本编辑区选择 **录制/脚本 → 游戏坐标**。浮窗每约 100ms 更新地图 ID、XYZ、朝向、存活/落地状态，不主动抢焦点；读取在独立线程进行。游戏断开后显示原因并尝试重连，失效坐标不能用于录制。窗口或无边框模式便于看到浮窗；独占全屏下的覆盖显示未验证。

浮窗内新增 **展开状态** 按钮，默认收起，点击后显示血量/最大血量与比例、体力、水平速度、移动状态、俯仰角、移动朝向、当前武器标识、蹲姿状态、复活时间、冻结标志和游戏状态时间；再次点击 **收起状态** 隐藏这些信息。未赋值的字段显示“未知”，失效快照会清除旧状态。速度、武器、蹲姿和复活时间按原始值标注，不猜测单位或枚举含义。

扩展数据由现有监控线程读取，路线录制和按钮仍可使用。跑图控制器默认只读取基础快照，不额外采集显示字段；状态栏不增加路线控制每次采样的字段数量。仅静态确认的弹药、装填和场景目标点暂未接入显示。

1. 新建或打开普通脚本，在列表中选中要插入路线的位置。
2. 浮窗点击 **开始录制路线**，切回游戏，手动走到目标位置。
3. 按 **F8**，或点击 **停止并插入脚本**，生成一条 **键鼠路线回放** 动作，然后保存脚本。键鼠输入及状态样本直接存入脚本 JSON，不依赖外部 Python 文件。
4. 回到录制起点并对齐原始朝向后执行。起点距离最多允许 150 单位、朝向误差最多 15°；朝向差按最短角度计算。游戏内鼠标灵敏度应与录制时一致。

路线录制和普通键鼠录制互斥，F8 在录制路线时会停止并插入路线。只保存游戏前台时的操作，忽略浮窗范围内的点击和滚轮；录制中失焦、切图、死亡、状态过期或传送会使录制失效。鼠标侧键尚不支持，会明确报错，不能当成左键回放。停留和等待期间也保留坐标样本。也可通过 **导入路线** 使用已有纯坐标路线 `examples/python/ssjj_route.json`；该按钮导入的是坐标导航路线。**复制坐标** 的文本不是执行动作。

键鼠路线回放按同一时间轴插值检查坐标，偏差超过 150 单位停止；此容差用于容纳游戏反馈和采样延迟，不是定位精度保证。回放过程中失焦、死亡、切图、读取失败、快照一秒不更新均停止并释放按键及鼠标按钮。暂停和全局守卫先释放输入、暂停时间轴，恢复时再按住当时应保持的键鼠；独立线程在主控制流程阻塞时也会释放输入。停止后重新执行从头开始。

浮窗拖动标题可移动。录制期间切图、死亡、状态过期或传送会使当前路线无效，需要取消后重录。关闭浮窗前要求插入或取消路线；退出主程序时，会尝试把有效路线插入草稿，无法保存时阻止退出并说明原因。

### 后台读取与后台输入

坐标读取不要求游戏前台。但当前自动跑图仍要求游戏前台，失焦会停止，不能让游戏最小化后自动跑图并同时使用键鼠做其他事。

2026-10-11 的定向消息探测：游戏在后台，`PostMessage(WM_KEYDOWN/UP)` 的 W、A 均成功入队，状态时间持续更新，但两个方向的坐标位移均为 0。因此本次没有启用未经验证的“后台输入”选项，也不自动抢回前台。现有只读坐标模块只能告诉控制器角色在哪里，不能直接让角色移动；真正的后台执行还需要单独验证可用且隔离于用户键鼠的游戏输入通道。失焦运行与最小化运行也不能视为同一能力。

## 数据来源与支持范围

- 外部只读 `OpenProcess` / `ReadProcessMemory`，没有注入或内存写入。只读取本人状态和地图 ID，不收集其他玩家的位置。
- 根据已加载的 Mono 元数据查找类与字段。运行时布局只支持已核实的 x64 `mono-2.0-bdwgc.dll`，SHA256：`7cf37b3415c2a168c724163be78109323ca6f75112eb549f2197a528eaebb4c9`。版本变化明确报错。
- 坐标来自 `MyPlayerEntity.BasicInfoComponent.Current` 的游戏状态快照，可能存在更新延迟；使用原始 XY 水平坐标、Z 高度，朝向使用 `_viewYaw`。
- 当前实读地图 ID 为 `100001`，与 `E:\SSJJ-map-analysis` 的缓存版本 `9a81a2a5059f8b732da623f373b38c81` 对应。离线三角网包含场景几何，不代表可行走网格，所以首版使用实走路线，不据此猜测通路。

## 使用

日常仍通过根目录 `run.bat` 启动最新源码，不需要 exe 构建。以下只读录制命令在项目根目录的 PowerShell 执行，使用与 `run.bat` 相同的 Python 和依赖目录：

```powershell
$env:PYTHONPATH="$PWD/.deps;$PWD/src"
& 'C:/Python313/python.exe' -m macroflow.execution.ssjj_state
```

命令只打印当前地图、本人坐标、朝向与状态。需要游戏已进入关卡，而且只有一个战斗客户端运行。

录制 30 秒路线，5 秒后开始：

```powershell
& 'C:/Python313/python.exe' -m macroflow.execution.ssjj_navigation --output examples/python/ssjj_route.json --seconds 30 --delay 5
```

切回游戏，手动走路线。每相距约 100 游戏单位记录一个点，并保留终点；死亡、切图或坐标大幅跳变会中止。没有走出有效路线会报错，已有路线文件只在新路线有效时替换。

录制结束后回到原起点，在 Macro 中打开 `examples/python/ssjj_follow_route.py`，通过现有 Python 脚本播放入口执行。脚本等待 5 秒，让你切回游戏，然后自动校准鼠标转向、逐点转向和前进。路线文件必须与该脚本在同一目录；可以复制这两个文件保存多条路线。

开始时需落地，并距起点不超过 250 游戏单位。直路持续按住 W，读取坐标时继续移动，小幅转向同时进行；朝向偏差超过 35° 时停止前进，调整到 20° 以内再走。25° 以上的路线拐角保留，直路中间点可在通过当前路段后推进，不会搜索并跳到其他相邻路线段。

直路中间点容差为 80，拐角与起点为 25，终点为 20 个原始游戏坐标单位，均按三维距离判断；中间点另要求高度差不超过 25，避免跨楼层误判。接近拐角和终点时，根据实测移动速度缩短前进时间；终点释放 W 后，必须取得更新的快照并再次确认到达。这些是控制器的判断阈值，真实游戏中的惯性、坐标延迟和碰撞仍可能影响实际精度。

控制器约每 10ms 检查状态，仅在游戏状态时间更新后计算下一次转向，不再为每次输入固定等待 150ms。Python 示例与原生路线动作共用播放器进程内的控制器，取消旧的逐次 `ssjj_input` RPC。前进授权最长 120ms，只有更新的状态才能续期；独立监控线程会在控制回调阻塞、暂停、停止或失焦时释放 W，全局守卫处理段执行前也释放。暂停和守卫处理耗时不计入路线控制超时。

失焦、角色死亡、地图改变、状态读取失败、快照一秒未更新、坐标大幅跳变、鼠标校准失败、三秒无进展或单点耗时超过 30 秒都会中止并报告原因。停止后重新执行会从路线开头开始。运行时不要手动改变朝向或移动。连续控制的设计、复用调研和后台模拟结果见 [连续跑图控制](ssjj-continuous-control.md)。

本次已随附实际录制并完成自动跟随的 `examples/python/ssjj_route.json`：地图 `100001`，39 个点，长度约 4188.6，起点 `(7411.51, 1510.58, 519.79)`，终点 `(5162.56, 983.81, 519.79)`，所有点高度一致。执行前需回到录制时开始走路的位置，也可按上面的命令从自己选的位置重新录制并覆盖它。
