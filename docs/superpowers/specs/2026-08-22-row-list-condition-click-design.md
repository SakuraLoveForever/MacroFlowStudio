# 列表逐行条件点击设计

## 目标

新增独立脚本动作“列表逐行条件点击”。动作在用户框选的列表区域内，从上到下逐行判断左右两个条件；同一行的左右条件全部满足时，点击该行并立即结束本轮扫描，不再检查更靠下的行。

典型配置：左侧读取 `11/12` 并判断 `/` 两侧数字不相等，右侧文字完全匹配“刚开始”，随后点击该行。

## 范围

- 只扫描当前框选区域内的可见行，不滚动画面。
- 左、右各有一个独立条件，两个条件都必须满足。
- 左右条件均可选择图片匹配、文字匹配或数字比较。
- 第一个匹配行被点击后结束该动作，脚本继续执行后续动作。
- 当前扫描没有匹配行时，可立即结束，或等待指定秒数后从顶部重新扫描。
- “等待后重新扫描”持续循环，直到命中、用户停止播放或脚本被外部终止。

## 配置界面

新增 `RowListConditionClickDialog`，配置项如下：

1. 列表区域：包含所有要扫描行的大区域。
2. 单行高度：每次向下平移的像素数，必须大于零且不能超过列表高度。
3. 第一行左侧条件区域：在列表动作内单独框选。
4. 第一行右侧条件区域：在列表动作内单独框选。
5. 第一行点击区域：命中后点击该区域中心；扫描后续行时按相同行距平移。
6. 左侧条件和右侧条件：各自独立选择类型及参数。
7. 未命中处理：
   - `结束动作`
   - `延时后重新扫描`，并填写重查间隔，单位使用现有时长输入控件。

第一行的左右条件区域和点击区域保存为相对列表左上角的坐标。框选时显示绝对屏幕区域，保存时转换为相对坐标，运行时再按列表位置和行序号计算实际区域。

## 条件类型

### 图片匹配

- 选择图片模块。
- 实时读取模块当前图片、相似度和忽略背景设置。
- 不使用模块绑定的绝对区域；识别区域始终使用本列表动作中框选的左侧或右侧行内区域。
- 模块不存在时明确报错，不使用保存动作里的旧图片回退。

### 文字匹配

- 填写期望文字。
- 匹配方式为“包含”或“完全相等”。
- OCR 只读取当前行对应的左侧或右侧区域。

### 数字比较

- 分隔符默认 `/`，必须非空。
- 解析分隔符左侧和右侧的整数。
- 关系可选“相等”或“不相等”。
- 无法解析为两个整数时，该条件视为不满足并继续下一行。

界面根据条件类型启用对应输入项，其他类型的输入项禁用且不写入保存结果。

## 数据结构

动作使用新的独立类型，不复用现有固定区域多条件动作：

```json
{
  "type": "row_list_condition_click",
  "list_region": [0, 0, 160, 340],
  "row_height": 26,
  "left_region": [0, 0, 80, 26],
  "right_region": [80, 0, 80, 26],
  "click_region": [90, 0, 60, 26],
  "left_condition": {
    "type": "number",
    "separator": "/",
    "relation": "not_equal"
  },
  "right_condition": {
    "type": "text",
    "expected_text": "刚开始",
    "match_mode": "equals"
  },
  "button": "left",
  "no_match_action": "retry",
  "retry_interval_ms": 1000
}
```

条件类型固定为 `image`、`text`、`number`。这是新动作，不增加旧结构兼容或迁移路径。

## 执行流程

1. 校验列表区域、行高、两个条件区域和点击区域。
2. 根据 `列表高度 / 单行高度` 计算完整可扫描行数，不扫描底部不足一整行的残余区域。
3. 从第 0 行开始，把第一行左右条件区域按 `行号 × 单行高度` 向下平移。
4. 先判断左侧条件；不满足时直接进入下一行，不执行右侧识别。
5. 左侧满足后判断同一行右侧条件。
6. 两侧都满足时，点击该行平移后的点击区域中心，结束动作并继续脚本。
7. 全部行均不满足时：
   - `结束动作`：不点击，直接继续脚本。
   - `延时后重新扫描`：可中断地等待指定时长，再从列表顶部开始新一轮。

任何一轮内一旦命中，立即停止向下扫描，也不再启动下一轮。

## 错误处理

- 区域无效、行高无效、条件参数缺失：保存配置时阻止保存并显示明确提示。
- 图片模块被删除：运行时终止该动作并报告模块名称或模块 ID。
- OCR 未识别、数字格式错误或图片未命中：仅视为当前条件不满足。
- 延时重查使用播放器现有可中断等待机制，确保停止热键可以立即生效。

## 代码边界

- `dialogs.py`：新动作配置窗口、条件控件启禁、区域相对坐标与保存校验。
- `player.py`：逐行扫描、条件执行、首个匹配点击和延时重查。
- `app.py`：动作菜单入口、动作摘要、OCR 依赖判断。
- `tests/test_core.py`：配置保存、区域平移、三种条件、短路判断、首个匹配、未命中结束和延时重查测试。

## 验收标准

- 用户只需框选列表及第一行的左右条件区域和点击区域。
- 左右条件可任意组合图片、文字、数字三种类型。
- 只会点击从上到下第一个同时满足左右条件的行。
- 命中后不再识别后续行。
- 未命中可立即结束，或按配置延时后从顶部重新扫描。
- 图片条件使用列表动作自己的行内区域。
- 后台自动化测试、源码编译、EXE 构建和产物静态验证通过；不启动可见界面测试。
