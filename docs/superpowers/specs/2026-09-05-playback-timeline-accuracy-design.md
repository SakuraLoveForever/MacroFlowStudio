# 回放时间轴与鼠标准确性设计

## 目标

第一阶段解决录制回放中“事件越多越慢”和“点击位置依赖上一条移动事件”两个核心问题，并为后续识别线程隔离、批量 UI 刷新保留清晰接口。

本阶段只改后台录制与播放器时序、坐标和诊断能力，不重排窗口、不迁移 UI 框架、不启动可见界面验证。

## 现状与根因

- `MacroRecorder._append` 当前把事件间隔四舍五入为 `delay_ms`，播放器在每条动作前等待该间隔；动作执行、状态回调、识别和守卫处理都发生在下一条动作之前，因此执行耗时会逐事件累积。
- `mouse_button` 录制事件已经保存 `x/y`，但 `MacroPlayer._execute_action` 只发送按钮状态，绝对坐标点击依赖上一条移动事件是否被录制。
- 注入转向在录制时只保存位移，播放器使用默认 `10ms` 持续时间，无法表达注入脉冲的真实起止时间。
- 相对移动、绝对移动和自动模式的语义已经存在，新的数据必须显式保存模式，不能让播放器猜测。

## 范围

### 本阶段包含

1. 高精度录制时间戳和绝对目标时间调度。
2. 普通执行迟到统计、严重迟到后的统一重设基准策略。
3. 绝对模式按钮事件的坐标定位、相对模式按钮事件的相对语义保留。
4. 点击和滚动前刷新尚未提交的移动数据，保证动作顺序。
5. 注入转向持续时间和位移的保存与回放。
6. 停止时释放所有已按下的键和鼠标按钮。
7. 可注入单调时钟、睡眠器和输入后端的后台测试接口。

### 本阶段不包含

- 全局识别线程迁移。识别线程将在 P2 单独设计，当前阶段只记录检测耗时和时间轴边界。
- `_ui` 批量刷新和日志队列。它将在 P3 单独修改，避免把 UI 线程问题与播放器时基同时改动。
- 网格条件窗口重排、主题统一和窗口视觉检查。
- 真实目标程序响应时间测量。测试只衡量发送端调度。

## 设计方案

### 1. 录制数据

每次录制建立一个单调时钟起点。每个被录制的事件保存相对录制起点的高精度时间：

```json
{
  "type": "mouse_button",
  "mode": "absolute",
  "x": 320,
  "y": 240,
  "button": "left",
  "down": true,
  "recorded_at_ms": 183.742
}
```

规则：

- 时间戳在回调入口立即取得，再执行模式判断、过滤、合并和通知。
- `recorded_at_ms` 使用 `perf_counter()` 的相对值，保留浮点精度，不逐段取整。
- `delay_ms` 不再作为录制事件的播放时基；显式等待动作仍使用自身的等待字段。
- 录制移动事件保存 `mode: absolute` 或 `mode: relative`。
- 鼠标按键事件保存事件发生时的屏幕坐标；绝对模式按键按下和释放都带坐标。
- 注入转向保存 `dx`、`dy`、`pulse_started_at_ms`、`pulse_duration_ms`。同一脉冲窗口内仍可合并位移，但持续时间取脉冲起点到最后一次注入的时长。

本次数据结构替换旧的逐段录制延时路径，不添加旧字段迁移或多套播放回退逻辑。手工配置动作的显式等待字段与录制事件时间轴是两种不同语义，播放器分别处理。

### 2. 时间轴调度器

新增 `src/macroflow/execution/timeline.py`，只依赖抽象时钟和等待函数，提供：

- `PlaybackTimeline.start()`：建立本次播放的单调起点。
- `wait_until(offset_ms)`：等待绝对目标时间；如果目标已到达则立即返回并记录迟到值。
- `mark_explicit_wait()`：声明识别等待、动作后等待、按住时长等用户显式时间已经消耗，后续录制时间轴从当前时刻重新建立基准。
- `rebase()`：严重迟到或跳转/重复/守卫处理段结束后，把后续时间轴基准重设为当前时刻。
- `TimingMetrics`：记录计划时间、实际发送时间、迟到、显式等待耗时和检测耗时。

普通录制事件按 `play_start + recorded_at_ms / playback_speed` 调度。发送一个事件本身消耗的时间会自然从下一事件的剩余等待中扣除，不再形成逐事件累加。

迟到策略：

- 轻微迟到：立即发送，记录到 `TimingMetrics`。
- 迟到超过统一阈值：立即发送，然后对后续事件执行一次 `rebase()`，禁止把积压事件瞬间连续发出。
- 不因为迟到丢弃按键、按钮、滚轮或相对位移事件。
- `playback_speed` 只缩放录制事件的目标时间，不缩放按键按住、点击保持、显式等待和转向脉冲持续时间。

### 3. 显式时间边界

以下动作不属于录制事件时间轴，完成后必须建立明确边界：

- `delay`、动作后的 `after_delay_ms`。
- 按键保持、鼠标点击保持、连续点击间隔。
- OCR、识图、条件扫描和超时等待。
- 守卫命中后的处理段。
- 跳转、重复和引用脚本切换。

边界处理结束后，后续录制事件从新的基准继续。这样识别或处理段的耗时不会造成后续输入积压，也不会无条件抵消用户显式配置的等待。

### 4. 鼠标坐标和顺序

#### 绝对模式

对 `mouse_button` 的每个事件，播放器先按事件中保存的坐标执行屏幕缩放和窗口边界钳制，再发送按钮状态。按钮事件不依赖前一条 `mouse_move`。

#### 相对模式

`mouse_move` 和 `turn` 继续发送相对位移；相对模式下的 `mouse_button` 不执行绝对定位，只发送按钮状态。事件必须带模式，播放器不得根据当前光标位置推断模式。

#### 移动刷新

- 点击和滚动回调进入时，先提交当前尚未落盘的注入转向。
- 相对/自动模式下，点击或滚动前强制提交待聚合的实体相对移动。
- 普通桌面绝对移动仍使用现有采样间隔，不把全部移动提高到 1ms。
- 录制回调只提交动作数据；UI 通知由后续批量刷新阶段处理。

### 5. 注入转向

转向动作的 `pulse_duration_ms` 用于分摊每个相对位移步骤的发送时间；持续时间为零时只发送位移，不增加额外等待。播放器不再为所有转向无条件追加默认 `10ms`。

如果转向动作发生严重迟到，位移仍全部发送，之后重设时间轴基准。

### 6. 诊断指标

播放器暴露本次播放的只读统计快照，并在播放结束时通过独立回调报告：

- 计划事件数量和已发送数量。
- 平均、P95、P99、最大调度迟到。
- 严重迟到次数和重设次数。
- 显式等待总耗时。
- 识别/守卫处理耗时（当前阶段由已有回调计时，不改变识别线程归属）。
- 停止请求到释放完成的耗时。

状态栏和 UI 日志不作为时间轴调度依赖，避免诊断输出反过来阻塞输入线程。

## 代码边界

- `src/macroflow/execution/timeline.py`：纯时间轴和统计对象，可使用虚拟时钟测试。
- `src/macroflow/input/recorder.py`：入口时间戳、事件模式、待移动刷新、转向脉冲字段。
- `src/macroflow/execution/player.py`：时间轴消费、显式边界、点击定位、转向持续时间、释放和统计回调。
- `src/macroflow/core/models.py`：新动作时间字段和录制屏幕相关模型常量；不加入 UI 逻辑。
- `tests/test_timeline.py`：虚拟时钟下的目标时间、迟到、重设、显式等待测试。
- `tests/test_recorder_timeline.py`：录制入口时间、点击顺序、模式、转向脉冲字段测试。
- `tests/test_core.py`：播放器集成、坐标缩放、释放保证和现有行为回归。

## 测试与验收

### 单元测试

- 1000 个事件的执行耗时不会累加到下一事件目标时间。
- 事件恰好到时、轻微迟到、严重迟到分别产生正确统计和调度行为。
- 跳转、重复、识别等待和守卫处理段结束后不会发送积压输入。
- 绝对按钮事件即使没有前置移动也定位到录制坐标。
- 相对按钮事件不调用绝对移动；相对位移不被转换成绝对坐标。
- 点击/滚动前待提交移动先于按钮/滚轮事件。
- 注入转向持续时间按脉冲起止计算，回放不额外附加默认 10ms。
- 停止会成对释放全部已按下的键和鼠标按钮。

### 后台基准

使用模拟输入后端和虚拟时钟验证逻辑后，再使用真实单调时钟运行：

- 10 秒、60 秒、10 分钟纯输入序列。
- 识别关闭、识别开启、注入固定延迟三种场景。
- 多显示器负坐标、屏幕缩放、窗口移动和拖拽坐标场景。
- 报告总时长误差、P95/P99/最大迟到、停止清理延迟。

首轮基线完成前不锁死最终指标；目标为 60 秒序列总误差不超过 100ms，空闲机器 P95 迟到不超过 5ms，停止到开始清理不超过 100ms。
