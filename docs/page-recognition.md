# 页面识别与「页面」动作

「页面」动作有两种来源：**战斗界面（内存）** 和 **大厅页面（整页截图）**。战斗端是 Unity Mono，可以直接读 `FreeUiManager` 里当前可见的 UI 名，不需要截图、也不受画面影响；大厅是 Adobe AIR/Flash，没有可用的页面状态 API，只能整屏截图比对。以前的做法是每个按钮都用「识图模块 + 阻塞等待 + 超时」去试，页面已经切过去还在等 3 秒，或者没切过去又白点一次。

页面判定的目标是把「现在是什么页面」变成一次廉价查询，脚本可以按页面直接走下一步。

## 战斗界面（内存）

- 读取链路（只读）：`FreeUiManager._instance._uis` 是 `Dictionary<string, SimpleFreeUI>`，键是服务端下发的中文界面名（如 `小地图UI`、`对战战绩UI`），值是 `SimpleFreeUI`，其 `_visible` 表示是否显示。
- 读取器：由本机内存插件提供（`local_plugins/ssjj_memory_plugin`），只连 `SSJJ_BattleClient_Unity.exe`；未安装插件时「读取当前」会提示不可用，动作按 3 秒退避重试。
- 不在对局时读不到内存：动作不会报错打断脚本，而是按 3 秒退避重试；超时提示里会说明「当前不在对局或读不到战斗内存」。
- 界面名取自游戏真实下发值，**用对话框的「读取当前」按钮抓**：进入对局 → 打开动作对话框 → 点「读取当前」，下拉里会出现当前存在的全部界面（可见的会列在提示里）。
- 执行期也会每 250 ms 读一次战斗界面（与截图跟踪共用节流），变化时写日志「战斗界面：小地图UI、对战战绩UI」。

## 页面库

- 目录：`images/全屏`（固定，不随模块模板目录变化）。
- 每张整屏截图就是一个页面，文件名去掉扩展名就是页面名，例如 `全屏_回到大厅.png` → `全屏_回到大厅`。
- 截图要求：与运行时同一窗口模式（全屏/铺满 16:9），不含鼠标指针；不同分辨率会缩放到 64×36 后比较。
- 目前库里有 84 张（大厅各子页面、弹窗、战斗加载/结算等），也是「点击游戏画面」这类瞬时状态的来源。
- 新增页面：把整屏截图按页面名放进该目录即可，对话框会立即列出；页面文件被用户改过时执行端会重新读取（每个播放实例缓存一次特征）。

## 「页面」动作

界面：脚本工具栏「◫ 页面」。

先选来源：

- **战斗界面（内存）**：填一个战斗界面名（如 `对战战绩UI`），判断它是否出现/消失；只在对局里有效，不截图。
- **大厅页面（整页截图）**：用 `images/全屏` 页面库里的整屏截图比对；适用于大厅与加载/结算画面。

| 字段 | 含义 |
| --- | --- |
| 来源 | 战斗界面（内存）/ 大厅页面（整页截图） |
| 战斗界面 | 界面名；点「读取当前」从游戏内存刷新候选，也可直接输入要等待的名字 |
| 页面 | 页面库中的页面名（截图来源） |
| 判定方式 | 等待出现 / 等待消失 / 立即判断 |
| 相似度阈值 | 与页面截图的相似度，默认 0.97（仅截图来源） |
| 超时时间 | 等待出现/消失的最长时间；勾选「一直等待」或填 0 表示不超时 |
| 检测间隔 | 轮询间隔，默认 150 ms |
| 成功后点击 | 命中后点击 `点击坐标`，支持左/右/中键与次数 |
| 超时后 | 继续下一行 / 结束当前脚本 / 跳转到脚本行 |
| 提醒 | 命中后显示浮动提醒 |
| 执行前延时 / 成功后延时 | 进入动作前后各等多久 |

执行语义（两种来源一致）：

- 等待出现：命中立即成功，否则按间隔重试到超时。
- 等待消失：目标不再出现立即成功，否则重试到超时。
- 立即判断：只查一次，命中成功；不命中直接走「超时后」分支（可用于「如果在某界面就点下一步，否则跳到别处」）。
- 命中后可点击固定坐标（按 1920×1080 记录，运行时自动缩放），随后继续下一行动作。
- 等待期间会记录「页面切换：xxx（相似度 99.3%）」到运行日志，便于确认脚本是不是卡在错误的页面假设上。

## 执行期页面跟踪

播放器在长时间等待（`_wait` ≥ 200 ms 的切片）里每 250 ms 刷新一次状态，变化时写一条日志：对局中优先读战斗界面（日志「战斗界面：…」），读不到战斗内存时退回整页截图判定（日志「页面切换：xxx（相似度 99.3%）」）。Python 逻辑也能读：

```python
def main(ctx):
    if ctx.ui_visible("对战战绩UI"):
        ctx.press("tab")
    if ctx.page_is("全屏_回到大厅"):
        ctx.run_module("进入战斗")
    ctx.log(f"当前页面：{ctx.page()}")
```

## 性能

| 项 | 实测（本机 1920×1080） |
| --- | --- |
| 单帧特征提取（含缩放） | ≈ 1.3 ms |
| 与全部 84 个页面匹配 | 约 0.2 ms 的矩阵乘 + 抓屏 |
| 首次加载页面库（解码 84 张 PNG） | ≈ 2.1 s，每个播放实例一次 |
| 执行期页面跟踪开销 | 4 帧/秒抓屏，约 5% 单核 |

## 已知风险

- 库里有 6 组「同底图 + 局部元素差异」的近似页面（异页相似度 0.95–0.998，提高分辨率也分不开）：
  - 专家 / 专家5 / 退出队伍；
  - 关闭全区找房 / 刚开始 / 游戏中测试 / 游戏中测试2；
  - 天降神器 / 结算关闭；
  - 开始战斗 / 战斗引擎；
  - 极速模式开始战斗 / 邮件（最难，任何整页方法都 0.94+）；
  - 王者乱斗 / 极速模式。

  页面动作「等待某个具体页面」不受影响（直接比对该页面截图）；但执行期「当前页面」名称可能在组内抖动，因此追踪带 0.02 的 margin 与「优先保留上一页」规则，日志里会写「与 X 相近」。
- 大厅页面动画/倒计时对整页特征影响很小：实测同页 10 帧自相似 0.9997–0.9999、分数 0.9954–0.9959；2% 面积动画约 0.977，计时器覆盖约 0.973，所以阈值取 0.97。若某页面实机分数更低，可在该动作里单独调低阈值，或补一张该页面状态的截图（同名会覆盖）。
- 战斗界面读取依赖 `SSJJ_BattleClient_Unity.exe`：单开、已进对局、GameGuard 允许只读。大厅阶段读不到战斗界面，这是预期行为；需要大厅判断时用整页截图来源。
- 抓屏用目标窗口所在的显示器；窗口化且带黑边/桌面时页面分数会明显下降，所以页面库与运行画面应使用同一窗口模式（建议全屏）。
