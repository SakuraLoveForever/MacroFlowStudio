# 定点动作与行进动作

2026-10-13。适用于通过 `run.bat` 启动的最新源码。

## 录制方式

在实时坐标面板开始录制，切回游戏后使用：

- **F7：行进点。** 从这个点开始，键盘、鼠标按钮和滚轮动作与前往下一点的导航并行。适合行进中跳跃、切枪、射击。
- **F6：定点动作。** 回放先到达此点并对齐水平朝向与俯仰角，停止移动，执行直到下一个标记之间的动作和等待；完成后释放本块输入，再前往下一点。
- **F8：停止并插入脚本。** 至少需要两个明确标记，终点也需标记。

例如：起点按 F7 → 走到开关前，停住并转正 → 按 F6 → 按 E 或点击 → 松开按键和鼠标 → 在原处按 F7 → 继续走 → 终点按 F7 → F8 保存。

F6 记录的是它**之后**的定点动作。用下一个 F7 结束定点块，再开始移动，可避免把后续步行耗时也录入定点等待。定点块保留完整录制时长，包括末尾等待；即使其中没有动作也会等待。跨定点块仍未抬起的键和按钮会在块末释放，不自动带到下一路段。

两个标记键只接受物理按键，每次按下只标记一次，不加入录制动作。若 F6 或 F7 已绑定脚本快捷键，先解除冲突。WASD 和转向由导航控制，新录制在监听和采集边界直接排除 WASD；其他按键、鼠标按钮和滚轮保留。鼠标移动轨迹不保存；标记点保存位置、水平朝向 yaw 和俯仰角 pitch，回放在每个标记点重新对齐。

## 起点与实走通路

回放前需回到起点 250 原始坐标单位以内。附近起点定位是短直线；超过距离会明确停止，不为未知区域自动生成长直线。请保持起点附近通畅。

F7 标记之间现在保存连续实走坐标，并沿原通路前进；行进动作按对应路线距离触发，同段成对按下/释放保留原按住时长。等待释放不会阻塞其他空间动作，原地停留在对应位置等待。暂停/守卫释放输入并冻结动作时钟，导航实际恢复后再恢复行进动作。两个标记位置相同时仍保留录制停留与动作。

无 `trajectory` 的旧版标记录制必须重录；不补成直线。终点 F7 后移动超过20单位要补充终点再保存。详见 [当前路线说明](ssjj-navigation.md)。

F6 要求动作期间位置、yaw 和 pitch 都保持在容差内。需要跳跃、行进或改变视角时使用 F7；射击后坐力等造成的视角偏离也可能使 F6 停止。水平与垂直输入分别校准方向和灵敏度，俯仰角使用双向探测避免视角上限截断响应。校准结果仅在本次回放中复用，修改游戏灵敏度后应重新开始回放。

### 原地转向但没有前进的反馈修正

2026-10-13 最新保存的三点路线与日志显示，回放在首点定位时停止：首点距离从 29.1 增大到 190.6，尚未进入 F7 行进段。该次日志没有 W 发送及校准值，不能据此断言键盘未发送或确认唯一实机原因；没有修改用户路线，也没有自动操作游戏做实机测试。

后台复现确认控制器会把分批到达的鼠标响应当成完整校准：真实灵敏度 0.5，16 单位探针仅先反馈 1 单位时缓存为 0.03125，随后反复转向、W 按下次数为零。已将未知灵敏度的探针改为完整观察 1 秒，并要求末尾至少两个新状态时间样本稳定；150/200/450/900ms 分批响应均有回归覆盖。普通转向等待已知灵敏度所预测的角度响应及稳定状态，期间不叠加纠偏；反馈稳定但与预测不符时观察满 1 秒再重新计算，始终无响应或未稳定则停止。超出该观察窗口的迟到响应仍不在本次验证范围内。

导航持续处理坐标、到点、暂停、守卫和 W 租约；低灵敏度下先减少方向偏差再前进。最终 yaw/pitch 对齐同样等待响应，避免状态时间更新而角度尚未更新时重复发送。校准增加固定观察耗时，不计入段内动作时钟。执行明细现在记录 W 按下已提交、W 松开，以及每 500ms 的实际坐标、yaw、方向差、距离和等待转向状态；系统提交成功不等于游戏已接受，仍以坐标反馈为准。W 事件在输入锁内排队、主线程锁外写日志，日志阻塞不会阻止监控线程释放输入。

## 验收与日志

沿用终点 20 个游戏原始坐标单位的判定阈值，水平朝向与俯仰角误差均不超过 1°。对齐朝向后，在同一状态快照中再核对坐标；发生位移超限或朝向精度不足会停止，不报告到达，不跳过必达点。20 个原始单位不是米，也不代表所有地图都已实测达到该精度。

定点块每 50 毫秒检查状态，并在每个输入发送前、每个暂停恢复输入前和块完成时额外检查位置与双轴朝向。发现偏离会释放输入、记录当前标记点并停止，不继续后续点。最后一个动作之后也会再检查，避免动作本身造成偏离后仍报告完成。检查依据客户端已发布的快照；尚未反映在快照中的变化无法被提前检测。

日志区分位置/朝向验收、定点动作、行进动作、前往下一点和“定点录制动作播放完成”。播放完成只表示录制输入与等待已执行，不能证明开关、门或 Boss 任务已完成。定点等待使用本段动作时钟，不经过移动进展检测；暂停和守卫处理暂停动作时钟，恢复前重新核对定点状态。停止、失焦、死亡、地图变化或快照冻结仍按现有规则释放输入并停止。

### 没有看到键鼠动作时如何定位

启动日志分别报告实际可回放的键盘、按钮、滚轮数量，以及输入数据中由导航替代的 WASD 原始事件数。新录制已不保存 WASD，其他按键仍可能包含按住后的自动重复，不能把原始事件数当成实际交互次数。F7 保存视角，鼠标移动轨迹本身不保存；按钮和滚轮独立录制。

执行顺序是首点定位 → 对齐该点 yaw/pitch → 启动该点动作段。首点未验收前录制输入发送数为零。失败提示现在带有真实标记点号、执行阶段和发送数量；导航卡住时还带实际/目标坐标、距离、高度差及水平朝向差。内部路线会细分插值点，内部“路线点 2”不等于用户的第二个 F7 标记。实际成功发送的每个录制事件写入执行明细，恢复按住状态不重复计入发送数量。

2026-10-13 用户反馈复查：日志载入 7 个标记点、200 条输入，在首点定位阶段停止。保存文件包含 198 条 W/A/D、2 条 Esc，没有按钮或滚轮；该文件实际交互回放数量为 2。第 3 个 F6 标记到下一标记相隔约 2,241 个单位，若要在这段移动，应以 F7 结束定点动作。没有修改用户保存的录制数据。旧日志不含失败快照，读取时游戏进程已退出，无法据此判断当时首点路径受阻的具体原因；本次修正可观测性，不声称已经修复实机障碍。

保存的每个 checkpoint 必须明确包含 `mode: "travel"` 或 `mode: "stationary"`，以及有效的 `pitch`。缺少模式或俯仰角的旧键鼠路线拒绝回放，请用 F6/F7 重新录制；没有增加旧格式迁移或兼容分支。纯坐标 `ssjj_route` 文件结构不变。

本次未增加自主识别敌人后攻击、自动瞄准、自动重登或强制结束游戏。这里的攻击仍是你录制的按键/按钮动作。
