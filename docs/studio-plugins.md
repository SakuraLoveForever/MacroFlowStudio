# 插件与侧栏

主界面增加「插件」页，提供定时条件执行和战斗端断线检测。侧栏删除启动与定时备份功能、快捷键脚本摘要和操作说明；快捷键设置保留。侧栏主要按钮两列，辅助按钮两到三列，使用圆角控件。保存覆盖前的历史归档保留。

## 定时条件执行

插件页使用紧凑圆角矩形卡片，按窗口宽度自动切换一至三列。卡片只显示名称、周期/类型与当前状态；右键卡片进入独立设置窗口，也支持键盘聚焦后按 Enter 或空格打开。插件设置不在列表中展开。点击「新增定时插件」可建立多个独立实例，默认勾选启用，右键可修改名称、周期、条件和动作块。每张卡片前的勾选框独立控制该插件；未填写条件或动作时显示「待配置」，不识别、不执行。列表可滚动。配置周期（小时和分钟两个输入框，默认 1 h 0 min）、图片或文字识别模块和代码块，然后启用并保存。文字条件复用模块的期望文字、匹配规则与识别区域。
每个实例从启用/保存时独立开始计时，修改其他实例不会重置其计时；达到周期后立即检查识别条件，未满足则按「间隔检测」设置重试（默认 1 min），直到满足所选结果。可选择识别成功或识别失败时执行；模板缺失、截图/OCR 异常不算识别失败。
代码块正常完成后重新开始整个周期；识图或执行失败时按「间隔检测」重试，避免每个轮询片重复触发。
等待、条件满足、执行中分别显示状态。重启软件恢复配置，重新计时，不补执行关闭软件期间的任务。

代码块编辑器复用主脚本动作分类、配置窗口和脚本引用，支持在选中行下插入、双击编辑、删除、移动及稳定跳转身份。
主脚本或工作流执行中，条件满足后在安全检查点暂停原流程、释放原按住输入，再独占执行插件；完成后恢复原位置与按住输入。工作流步骤间的剩余等待也保留，插件耗时不抵扣这段等待。插件拥有自己的结束/跳转边界和识别作用域；引用脚本的识别作用域也归插件所有。普通主脚本守卫不会在插件内部混入触发。多个插件同时满足条件时按卡片顺序串行执行，共享一个播放器，避免键鼠冲突。
空闲时使用同一个主播放器运行插件代码块，避免另建一个键鼠执行器。录制或暂停期间不启动插件执行。F12 只取消待执行和运行中的插件，不会改动卡片的启用勾选（否则停止一次再保存设置，下次打开插件就被记成未启用）。停止后卡片状态显示「已停止，下次执行时恢复」；下一次开始执行脚本或工作流时按保存的启用偏好自动重新计时。

断线检测移至插件页，检测策略保留原实现。重复创建界面复用同一监控实例。

## 多实例实现与复用核验（2026-10-14）

应用配置采用 `interval_condition_plugins` 列表，每项有独立 ID、名称、启用状态、周期、条件和动作块；已移除单实例配置入口，不迁移旧单实例字段。

本轮核验 [schedule](https://github.com/dbader/schedule)（12271 Star，MIT，最近推送 2024-05-25）、[APScheduler](https://github.com/agronholm/apscheduler)（7655 Star，MIT，最近推送 2026-10-12）及已有 UI 依赖 [ttkbootstrap](https://github.com/israel-dryer/ttkbootstrap)（2660 Star，MIT，最近推送 2026-09-12），均未归档。推送日期不能确认实质维护，最新发布本轮未单独核验。

schedule 和 APScheduler 能调度多任务，但不能替代识别门槛、插件作用域和播放器输入独占，接入仍需重复现有状态机，未增加这些依赖。直接复用现有单插件状态机形成实例集合，保留一个监控线程与一个串行播放器；滚动列表采用已有 ttkbootstrap 的 ScrolledFrame，其 API 与实现已核对本地安装源码。仅增加 ID 集合、复用滚动容器，集成成本低，未引入额外组件或复制候选代码。


## 模块与界面细化

模块对象增加「识图」分类，只输出图片/文字识别的成功或失败，忽略并清除点击、备用点击、附加动作、定时动作等副作用。调用方仍可按该结果继续、跳转或运行自己的分支。模块管理任意分类的右键菜单均有「切换分类」，当前分类不可选；切换保留对象 ID 和引用关系。

定时插件二级编辑窗口支持删除，删除按钮后必须再次确认。启用卡片采用绿色背景/边框和状态文字，禁用采用普通灰色。卡片按实际复选框和文字尺寸排列，并根据内容计算高度，避免遮挡；列表不再把卡片拉宽占满空间。统一工具栏按钮字号和内边距，缩小重复次数及工作流选择框，长选中值可横向滚动。

模块管理右键「复制…」复用双击参数编辑窗口。以原参数的深拷贝作为草稿，取消不创建，保存分配独立模块 ID；特殊模块副本保留原固定动作类型。
