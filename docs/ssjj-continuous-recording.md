# SSJJ 键鼠路线录制（F7 纠正点）

## 使用

1. 通过项目根目录 `run.bat` 启动源码，进入游戏关卡。
2. 新建或打开普通脚本，点「⌖ 游戏坐标」，等坐标正常更新。
3. 按 F8 或点「开始录制」——**在游戏外、大厅或加载中按都可以**：这时只准备录制器，进入关卡、能读到本人角色时才真正开始计时，并把那一刻当作起点（自动成为第 1 个纠正点）。随后正常走：WASD、镜头、点击、滚轮都会被录下来。
4. 走到需要纠偏的地方（拐角、跳台、贴边、长时间直线之后）按一次 **F7**（或点浮窗上的「标记纠正点」），该处位置与朝向被记为纠正点。不用每帧标点，只在“跑歪了需要重新对齐”的地方标。**纠正点只记「距上一点的间隔」**（起点是第 1 个点，间隔固定为 0）：录到的间隔就是相邻两个纠正点之间的毫秒数，绝对时刻由回放时累加得到。
5. 到终点落地停稳后按 F8（或点「停止并插入」），路线插入脚本，再保存脚本文件。**在游戏里按或切到游戏外再按都可以**：停止只读内存，不要求游戏在前台，也不会把游戏窗口切到前台。
6. 在同一地图保持游戏前台按 F9。程序先从本局实际位置直线走到第 1 个纠正点并对齐朝向，然后**直接按录制的按键和鼠标往下执行**；每到一个纠正点，再用内存坐标把位置和朝向纠回来，继续回放。F12 停止。**这条路线开始执行时「SSJJ · 游戏监测」浮窗自动出现**（之前关掉了也会自动打开，和录制时一样不抢游戏前台）；执行结束只收回自动打开的那一个，自己手动打开的浮窗保持显示。路线里的「从此行开始执行」试跑同样会把它放出来。
7. 想改录好的路线：在脚本里双击那条坐标路线动作，打开的是**模块化编辑**——纠正点一行一个（显示成「距上一点 N ms」）、键鼠输入一行一个（按键显示成 W/E/SPACE），双击某一行只改那一项；还能**插入键盘按键、鼠标按键或延时**（延时把该时刻之后的输入、纠正点、轨迹与录制时长一起后移）。保存前会按录制格式校验，地图、轨迹采样和录制时间轴保持不变。

开始采集前不会记录浮窗上的操作。**开始录制不要求已经在关卡里**：游戏外/大厅按 F8 后处于“等待进入对局”，这段读不到坐标的时间不会作废录制；读到第一帧对局状态才开始计时并记起点。**开始和结束也不要求游戏在前台**：前台只决定「要不要把实体输入录进去」——在游戏外按的键鼠本来就不该进这条路线，所以直接丢掉，不会判录制失效；停止时读内存与焦点无关，也不会把游戏窗口抢到前台。之后死亡、换图、坐标跳变、以及游戏中途的采样中断仍会使录制失效，需要取消后重录；只有一种例外：采样在**末尾**中断、而且游戏不再发布新状态（对战端已退出、失焦后画面停更、切场景后再也没恢复），说明中断就是录制的结尾，这时按 F8 会按中断前的数据收尾并插入，状态行会写明中断原因和「已按中断前的数据收尾」，请照常核对路线是否完整。

## 数据与执行约束

- **路线常用键来自战斗端识别状态**：直接只读 `InputComponent.KeyStates`；表内的键不依赖桌面键盘钩子或前台过滤。表外的键和鼠标继续使用现有录制器，同一键只使用一个来源。
- 按键采样使用独立读取句柄和线程，目标间隔 5 ms，避免坐标读取重试阻塞键盘。Windows 下使用 Python 高精度休眠；2026-10-14 只读实测平均 5.723 ms、最长 11.798 ms，1398 次读取无错误；用户另一次操作采样读到了 W、空格、E 的按下和松开。按键采集只覆盖对战端在跑的时间：对战端退出后按键表不存在，面板会显示「录制已中断」，此时仍可按「停止并插入」保留已录部分。
- 游戏当前状态表有 62 个 Unity 键码，合并主键盘/小键盘 ENTER 后为 61 个 Windows 虚键码；Ctrl/Shift 等表外的键仍由实体输入监听记录，不宣称游戏状态表覆盖它们。软件快捷键和用户配置的触发键继续排除。状态采样并非事件日志，不能保证捕获两次采样之间已结束的极短点按；超过 100 ms 未得到有效采样时标记录制失败，禁止静默保存可能漏键的路线。停止时按「中断之后游戏是否又发布了新状态」区分两种中断：新状态说明断档落在路线中间、那段时间的输入已经漏了，仍然整条拒绝；没有新状态（对战端已退出、失焦后画面停更）说明中断就是录制的结尾，允许按最后一帧有效数据停止并插入，并在状态行与活动行写明中断原因和「已按中断前的数据收尾」。
- 字段与集合布局通过当前战斗端的只读内存核验：`Contexts.userCommand` → 输入实体 → `InputComponent.KeyStates`，字典每项为 16 字节；读取检查版本、数组长度和状态值。REA 的大程序集元数据解析达到表示预算上限，因此未将其不完整成员解析作为字段布局证据。

- **两个纠正点之间是纯回放**：录制到的 WASD、其他按键、相对镜头位移、鼠标键、滚轮按原录制时间轴依次重发，中间不做任何逐点坐标跟踪。因此不会出现“每读到一个采样点就纠一次航向、冲过头再折返”的折线走。
- **只有纠正点用内存坐标**：直线走到记录位置（终点容差 20 个游戏坐标单位），并按录制 yaw/pitch 对齐（±1°）；对齐完成后继续回放。起点固定是第 1 个纠正点，终点姿态在收尾阶段再对齐一次并校验落地。
- **纠正点只记「距上一点的间隔」**：每个点存 `gap_ms`（距上一个纠正点的毫秒数；起点是第 1 个点，固定为 0），回放、编辑器与「从此行开始执行」都按累加出来的绝对时刻工作。间隔非负，所以列表顺序就是时间顺序；改一个间隔只影响它自己和后面顺延的点，在某个纠正点前插入延时也只加长那一段间隔，不会牵动别的点。旧的「纠正点记绝对时间（`at_ms`）」格式不再支持：执行和保存会直接报「还是旧的绝对时间格式，请重新录制」，打开编辑器同样被拒绝，不做格式转换。
- 纠正点之间保留录制的按住时长与间隔；暂停、F12、守卫会立刻释放按住输入，恢复后补按回去，回放时钟在暂停和纠偏期间暂停，不拉长录制时长。
- 录制内容：WASD 与其他按键、相对镜头位移（dx/dy）、鼠标左右中键、滚轮。浮窗上的点击按坐标排除；F7/F8/F9/F10/F12 属于软件快捷键，不录进路线。
- 采样仍以约 0.05 秒一次读取内存状态，用于校验（起终点落地、时间轴完整、坐标跳变、快照停更）；它不再参与行走控制。停止时现读一帧作为末态：这一帧和上一帧记录之间跨度超过 3 秒、或位置跳变超过 1000，会按「末尾中断／整条作废」规则处理（见上一条），不再要求「坐标必须新鲜」。
- 录制相对位移要求游戏在前台（人在游戏外时实体输入不录进路线）；镜头灵敏度在执行时测量一次并复用，按最短角差一次提交完整转向。
- 跑图前会按进程找到**战斗端窗口**并切到前台：脚本里绑定的「前置窗口」通常是启动器（`MicroClient.exe` 的 `SSJJ_MainWnd`），启动器在前台不等于战斗端在前台；自己切不过去时才提示「游戏不在前台」，此时点一下游戏画面即可。录制输入期间只判断前台、不主动抢前台；停止录制只看内存，不判断前台也不切窗口。
- 旧的“连续轨迹纠偏”录制格式与更早的 F6/F7 checkpoint 格式都不再支持，需要重新录制；没有加入兼容转换。普通 `ssjj_route` 导入与通用键鼠录制保持各自用途。
- **不在这一局游戏里就跳过**：执行时战斗端没开、没进对局、内存/状态读不出来、换图或切场景、战斗端不在前台（自动切前台失败）时，这条路线记一条「跳过键鼠连续路线／路线中断／终点验收跳过」日志并跳过剩余步骤，脚本继续往下执行，输入不会发给别的窗口；死亡、坐标无效、导航超时这类真正的执行错误仍按失败处理。
- **末尾中断也能插入**：按末尾中断收尾时会把时间轴补到「停止」这一刻，再产出动作：游戏停更/退出之后录到的最后几条按键通常晚于最后一帧状态，不补这一帧的话 `duration_ms` 盖不住输入时间，校验会报「无效的路线输入时间」，浮窗会一直卡在「录制中」、按停止没有反应。校验仍不通过时，浮窗提示会带上「请点浮窗『取消录制』后重录」，不会再无声卡住。

## 后台验证

2026-10-15 工作流续行：路线运行和终点验收中的状态读取、冻结、死亡、导航等运行错误会记录“未完成”及原因，释放路线输入、关闭监控线程并跳过剩余路线，让后续脚本动作和工作流继续执行。终点未完成不能记作验收成功。F12／主动停止和脚本跳转请求仍按原有控制流生效；路线格式在执行前校验，配置错误不当作运行时状态错误吞掉。

2026-10-15 回放调度停顿修复：300 ms 输入授权到期仍会由独立线程释放当前按住的键鼠，但不再直接报“游戏状态读取超时”并结束工作流。回放线程恢复后重新核对前台、地图、存活状态及快照更新；核验通过才恢复原先按住的键鼠，并扣除松键期间的回放时间，避免后续动作集中补发。恢复日志包含停顿时所在阶段。实际输入错误、失焦、死亡、换图和状态冻结继续沿用原有停止／中断处理。后台模拟覆盖停顿后恢复、剩余按住时长，以及死亡、换图和冻结时不重新按键。

导航定时步进到时或主动到点停步时，先松开 W，再短按 Shift 40 ms 刹停；连续路线进入后续纠正点和终点验收前也会先刹停，再读取停稳位置。暂停、停止、失焦和异常收尾只释放按键，不额外按下 Shift；脚本已持有 Shift 时不会覆盖其状态。Shift 短按复用既有输入接口与看门狗，不新增依赖，录制事件本身保持原时间轴。

使用与 `run.bat` 相同的 Python 3.13 与 `.deps`/`src` 路径运行 `test_ssjj*.py`，覆盖 F7 标点、录制内容（WASD/镜头/点击/滚轮/面板点击排除）、纠正点之间按录制时间轴原样回放、纠正点位置与朝向对齐、出生点偏离、暂停与守卫恢复、异常释放和格式校验。

没有启动游戏或可见软件界面，没有构建 EXE；模拟验证不能替代实际地图的效果验证。
