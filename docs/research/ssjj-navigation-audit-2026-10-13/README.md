# 自动跑图审计与 REA 静态分析

日期：2026-10-13。范围：当前工作区源码、既有运行日志、研究目录程序及配套材料。未启动应用或游戏界面，未发送真实输入，未构建或打包。当前工作区有大量既有未提交改动，报告针对本轮读取的版本；本次不修改产品行为。

后续状态：本文保留修改前的审计结论。用户随后授权实施，当前源码已保存实走通路并按空间进度触发动作；`reproduce.py` 已更新为检验修正后的空间触发和未知障碍限制。原有“产品尚未修复”、98项测试及行号均是审计时的历史状态，最新行为见 `docs/ssjj-navigation.md` 和实施计划。

## 结论

当前自动跑图具备坐标反馈、转向校准、连续前进和异常释放按键，但核心仍是“标记点之间走直线，加上定时动作”。缺少真实录制通路、空间动作触发、障碍恢复和关卡状态驱动。继续只调延迟或放宽到达容差不能补齐这些能力。

当前已能独立确认两项能力缺口：有限宽障碍前不会绕行；相同录制跳跃在不同速度下发生于不同位置。历史首点定位失败另涉及输入/反馈闭环，具体根因仍未确定，不能把全部失败归为碰撞。

### 历史日志不是本轮实测

`logs/2026-10-13/MacroFlow_02-17-14-660_34580.log:25–29`：首点定位距离 29.1；约 4 秒后剩余距离 190.6、水平朝向差 45.4°、高度差 0。失败发生在首点定位，录制输入发送 0/0。这不能归因于录制动作竞争，也不符合单纯“一直原地不动”的描述。

这些日志未绑定源码提交版本，且没有完整输入、读数和时延轨迹；不能断言当前源码仍发生同一问题，或直接认定 yaw 符号相反。现有模拟用 cos(yaw)、sin(yaw) 生成移动方向，验证的是该假设下控制器行为，不能独立证明游戏坐标约定。

### 后台复现

`reproduce.py` 复用项目现有 Simulation 和输入替身，完全不启动游戏、不调用真实键鼠输入：

1. 从 (0,0,0) 到 (600,0,0)，x=200 且 |y|<100 有有限宽墙：控制器停在墙前，最大横向位移 0，最终报无进展。墙侧有路，但系统没有规划或探索该路。
2. 同一路段在 500ms 按空格，速度 300/600/1200 时触发位置分别约 x=150/300/600。证明动作与时间绑定，未与空间障碍位置绑定。

复现脚本退出成功表示这些现有缺口被复现，不表示导航功能已修复。

### 逆向限制

- `binary_session` 显示 Ghidra 未配置且 Java 不可用，IDA MCP 未配置，Hopper 不支持当前 Windows 主机。原生函数反编译与调用链分析无法开展；没有擅自安装工具链或启动目标。
- ZeusTool 的 `inspect_pe_resources` 返回 `Resource range is not entirely file-backed in one section`，因此没有资源树成功结果。该错误本身不能证明具体保护方案。
- 没有打开原生分析数据库，无需关闭此类数据库。没有执行授权界面操作或修改参考二进制。
- 原生核心算法、mi_startPath 的实际调用链、图寻路算法与脱困策略仍未还原。本轮是有限静态分析，不能称“完整逆向成功”。

## 研究材料能提供什么

`研究/工业1.txt` 直接展示等待坐标、清路径、11 次 mi_addPoint、启动路径、查询运行状态和路径索引。点有第四个参数，但本轮未证明其枚举语义；不能照抄 5/6 作为本项目动作类型。它检查 idx>16，而显式点数为 11，不能直接移植结束条件。

`研究/SSJJ-map-analysis/docs/zeustool-runtime-analysis.md` 是 2026-10-10 的既有分析，不是本轮 REA 输出。该报告列出战斗、卡住处理、图目标、Boss/出口节点接口，以及输入 Hook 机制；其本人也注明未追完 mi_startPath 调用链。可借鉴的是职责拆分：状态读取、路线决策、动作执行、恢复、任务阶段各自独立。接口名称不证明 A*、NavMesh 或已能通关。

`研究/挂机脚本/极速关卡自动坐标.json` 的 x/y、点击延迟和退队步骤属于界面流程配置，不能直接当作世界坐标导航网格。

`docs/research/ssjj-pve/2026-10-12-enemy-telemetry.md` 已有普通怪/Boss 坐标、血量与死亡的历史采样；现有独立探针尚未接入导航决策。应复用这些研究，但敌我、视线、状态新鲜度和可攻击条件仍需核对，不能看到 Bot 就触发战斗。

已有离线地图导出可作为后续规划输入，不过渲染三角网、碰撞数据和可行走区域并不等价。需要验证坐标转换、角色半径/高度、坡度、楼层连通、跳跃和动态门，才能用于通路图。

## 建议实施顺序与验收

1. **先保证短距离运动闭环可信。** 为已有输入/状态记录增加时间、位移投影、转向请求及响应关联；分清未转向、反向移动、移动被阻挡、读取过期。用留存数据做离线重放。验收包含角度环绕、延迟变化、细碎响应及错误方向；不靠放大容差把失败变成功。
2. **保存实走通路。** F6/F7 保留动作语义，同时采集空间轨迹，保留拐角与高差，回放沿通路推进。自动回起点也必须沿已知可达通路；未知区域明确停止。验收为绕墙、U 形通道、临近平行路段和上下层不切线、不串段。
3. **将动作锚定空间与状态。** 跳跃用位置/落地条件，交互用交互结果，定点动作验证完成条件；时间只控制动作内部节奏及超时。验收为 0.5/1/2 倍速度、暂停、受阻后仍在正确位置执行一次。
4. **增加有界恢复与重入。** 区分转向未响应、障碍、悬空、受击、死亡、切图；只在有已知通路时尝试侧路或回退，限制次数并验证恢复结果。保留暂停/停止/失焦立即释放输入。禁止无限随机跳跃掩盖路径错误。
5. **再接关卡决策与地图规划。** 明确行进、交互、等待门开、战斗、死亡恢复、完成阶段；接入经核实的 PVE 状态与通路图。先完成一个固定关卡的可重复闭环，再扩展地图。选择新依赖前按 AGENTS.md 重新检索 GitHub、核对维护和许可证；本轮未新增功能或依赖，未作新的选型承诺。
